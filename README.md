# K-RALLY 重制版（Android / Web 原型）

用解包出的原作文本 + 完全重画的程序化美术 + 程序化音频，从零实现的可玩原型。
含生涯模式、车库、商店、车辆升级、AI 战术层。

## 运行

| 方式 | 命令 |
|---|---|
| 浏览器 | 直接打开 `index.html`（或 `python -m http.server` 后访问） |
| Android | 安装 `KRallyRemake.apk`（minSdk 24 / targetSdk 35） |

操作：WASD / 方向键 驾驶，SPACE 开火，SHIFT 弃武器，P 暂停，M 静音；手机端用屏幕虚拟按键。

## 玩法系统

### 生涯（CAREER）
三档锦标赛，逐级解锁：

| 赛事 | 场次 | 圈数 | AI 强度 | 冠军奖励 |
|---|---|---|---|---|
| ROOKIE CUP | 3 | 3 | 0.86 | $800 / 150 XP |
| CHAMPIONSHIP | 4 | 3 | 0.95 | $2500 / 400 XP |
| MASTER LEAGUE | 4 | 4 | 1.03 | $6000 / 900 XP |

每场按名次发奖金（1st $600 / 2nd $380 / 3rd $220 / 4th $120）+ XP。前一档完成才解锁下一档。

### 车库（GARAGE）
4 辆车，速度 / 加速 / 抓地三条属性，可切换当前用车，属性以进度条呈现。

### 商店（SHOP）
- **CARS**：KITE（初始）/ VIPER $2400 / WRAITH $6500 / NOVA-X $13000
- **UPGRADES**：ENGINE（速度 +16 / 加速 +12，3 级）、TIRES（抓地 +0.05/级）、
  WEAPONS（开局自带 ROCKET，等级=弹药）

### 存档
localStorage `krally_save_v2`：现金、XP、车辆、每车升级、锦标赛进度、最佳圈。

## AI

### 基础行为
- 前视点循迹 + 弯道减速 + 随机开火
- 避让：对 150px 内对手施加侧向斥力，正前方 110px 内减速；对 130px 内地雷绕行

避让 A/B 实测（50 秒）：碰撞 871 → 59，完赛时间 0:42.85 → 0:37.97。

### 战术层（封堵 / 撞人 / 抢道具）

每 0.2~0.35 秒决策一次，三种战术按优先级竞选：

| 战术 | 触发条件 | 行为 |
|---|---|---|
| **抢道具** | 230px 内有道具，且手里没武器或类型不同 | 直奔道具；若同时有对手在抢且自己带 TURBO，直接开加速抢先 |
| **故意撞人** | 130px 内、偏角 < 1.15 弧度、目标不比我快太多 | 对准对方车身撞，命中前给一点加速；**2.5~4.5 秒冷却**避免一路撞过去 |
| **封堵** | 后方 200px 内有更快/更近的车 | 把车摆到追击者的行车线上（前方 95px 处横向对齐） |

每个车手有独立性格参数（aggr / block / loot）：

| 车手 | aggr / block / loot | 表现 |
|---|---|---|
| JURIJ | 0.34 / 0.46 / 0.55 | 均衡 |
| MARKO | **0.88** / 0.50 / 0.38 | 最爱撞人 |
| DR.DRILL | 0.38 / **0.92** / 0.42 | 封堵大师 |
| NOVA | 0.50 / 0.32 / **0.92** | 抢道具狂 |

撞击目标会从避让列表中排除，否则两个力互相抵消（撞不到人）。

### 战术层实测（40 秒、3 圈、5 次取样平均）

| 指标 | 战术开启 | 战术关闭 |
|---|---|---|
| 封堵时长 | 23.6 s | 0 |
| 撞人时长 | 3.1 s | 0 |
| 抢道具时长 | 17.3 s | 0 |
| AI 拾取道具数 | **15.8** | 11.6 |
| 玩家拾取道具数 | 6.4 | 6.6 |
| 接触帧数 | 215 | 48 |

抢道具让 AI 多拿约 36% 的道具；接触帧数上升是撞人和封堵的预期代价（一帧贴身算一次）。


## 渲染：高视角俯视 + 精细地图

原作是"从天空俯视"的视角，地图本身是重点。现在渲染层是一次性烘焙的整张地图：

`js/terrain.js` 在开赛时把整条赛道画进一张大 canvas（约 2600×2000），之后每帧只做一次 drawImage，性能稳定：

| 层次 | 内容 |
|---|---|
| 地形 | 底色 + 220 块色斑 + 90 块泥土，制造起伏感 |
| 沥青 | 主体 + 9000 个颗粒点 + 260 块磨损色块 + 双轮胎印 |
| 路肩 | 沿赛道每 26px 一块红白相间，两侧都画 |
| 标线 | 白色边线 + 中线虚线 + 起跑格 |
| 立体感 | 路基偏移阴影（右下偏移 16/18px） |
| 场景 | 520 棵树/岩石 + 260 个贴边木桶 + 26 栋建筑 |
| 弯道 | 按曲率自动放置红白箭头牌 |
| 广告牌 | 14 块，长边顺赛道（俯视时可读） |
| 路灯 | 每 300px 一对，带 62px 暖光晕 |
| 小地图 | 直接用烘焙图做缩略图，不再是矢量线框 |

相机改为**拉远 + 前瞻**：视野高度固定约 900 世界单位、宽度上限 1700；相机朝车头方向预瞄（最多 160 单位），配合暗角，形成"从天空看下去"的观感。

画布自适应视口（`resizeCanvas`），横屏手机/超宽屏都不再拉伸变形。

**已知问题**：Android WebView 的视口宽度上报异常（约 350 CSS px），已改用 `width=980` 的布局视口让 WebView 自行缩放，目前右侧有轻微裁切，待进一步校准。

## 渲染：俯视写实地图

`js/terrain.js` 在开赛时把整条赛道烘焙成一张约 2500×1950 的大图（实测 36ms），之后每帧只做一次 drawImage：

| 层次 | 手法 |
|---|---|
| 草地 | 底色 + 噪点贴图 + 240 个径向色斑 + 2600 根草 + 1200 颗碎石 + 260 丛灌木 |
| 沥青 | 颗粒噪点pattern + 4 条车轮磨痕 + 220 处油渍/修补 + 140 条裂缝 |
| 路肩 | 红白相间，带侧面阴影和顶部高光，做出立体感 |
| 立体感 | 路基环境光遮蔽（三层偏移描边）+ 整体左上打光 |
| 场景 | 树/岩石用**预渲染精灵**（3 种树 + 2 种岩石）+ 软阴影贴图；20 栋建筑带屋顶颗粒、空调外机、投影 |
| 细节 | 护栏、弯道箭头牌、广告牌、成对路灯（70px 光晕） |

车辆（`js/art.js`）重画为写实俯视：金属漆渐变 + 边缘高光 + 挡风玻璃反光条 + 轮胎纹路 + 前后灯 + 刹车红光 + 预渲染软阴影贴图。

### 性能上的两个坑

1. **不能用 `ctx.filter='blur()'`**：烘焙时逐物件模糊会让整张图从 36ms 涨到几分钟；改成预渲染径向渐变精灵后恢复。
2. 同理每帧给每辆车加 blur 直接卡死渲染循环 —— 现在阴影全部是贴图。

## Android 视口问题（已修）

设备上实测 `inner 980×441 dpr 2.625 canvas 980×441@0,0`。根因是 WebView 的布局视口计算，最终用
`<meta name="viewport" content="width=980">` 让 WebView 按 980 宽布局再整体缩放，画布终于铺满全屏。

遗留：980 宽布局下部分菜单卡片右侧有轻微溢出，需要再调 grid 与容器宽度。

## 地面与树冠（写实化第二轮）

**地面**改成多尺度叠加，不再是几块大色斑：

| 层 | 做法 |
|---|---|
| 底纹 | 192px 噪点 pattern，叠在主题底色上 |
| 大起伏 | 90 个 240–700px 柔和色斑（alpha 0.12–0.22） |
| 中斑驳 | 1400 个 14–84px 色斑 —— 这一层是「不糊」的关键 |
| 草簇 | 520 个 22–77px 明暗团，模拟成片草皮 |
| 泥土 | 110 块不规则多边形（每块形状随机） |
| 草叶 | 9000 根带弧度、三种明度的短笔画 |
| 颗粒 | 2400 颗碎石 + 6000 个 1px 噪点 |
| 云影 | 26 片压扁的暗椭圆，压出层次 |

色斑全部预渲染成精灵再 stamp，避免几千次 createRadialGradient 拖慢烘焙。

**树冠**改成真正的叶团：

- 阔叶树：6–10 个叶团按随机角度堆叠，每个叶团用「亮部 → 中间调 → 近黑」径向渐变，再加 40 个叶面高光点和中心压暗
- 针叶树：三层锥形叶团（雪原 / 丛林用）
- 每棵树独立投影，4 种阔叶 + 1 种针叶轮换

## 车手影响生涯

每个车手有**赞助商**和**特权**，直接改变手感与经济：

| 项目 | 影响 |
|---|---|
| speed / accel / grip | 玩家车属性倍率 |
| armor | 受到伤害除以该值（抗撞） |
| prize / xp | 奖金、经验倍率（生涯与快速赛都生效） |
| pickup | 拾取判定半径倍率 |

举例：FIXER 奖金 +18%（$600 → $708）；THUGS 抗撞 +30% 但奖金 −10%（$600 → $540）；SWEETHART 道具范围 +35%；VULTAR 极速 +6% 抓地 −3%。

界面：生涯页顶部有车手条（头像 / 赞助商 / 特权 / 生涯胜场 / 换车手按钮），车手选择存进存档，完成锦标赛会给该车手记一场胜场。

**自测**：test_drivers.html 覆盖 163 项断言（14 人特权字段合法、赞助商不重复、倍率生效、奖金换算、存档持久化），当前 163/163 通过。

## AI 也吃自己的特权

以前只有玩家套用车手特权，AI 只是难度系数。现在发车时按 AI 自己的车手数据算：

```
speed  = aiBase * perk.speed
accel  = aiBase * perk.accel
handling = aiBase * perk.grip
armor  = perk.armor        // 被火箭/地雷打时伤害除以它
pickup = perk.pickup       // 抢道具箱的判定半径
```

实测一局（玩家 JURIJ）：`JURIJ v=418 arm=1.00`、`MARKO v=403 arm=1.28`、`DR.DRILL arm=1.05`、`RUSTY v=390 arm=1.35` —— MARKO 真的更抗撞，RUSTY 真的更慢但更硬。

保留英文的：车手本名（JURIJ/MARKO…）、赞助商名（品牌）、车款型号（KITE/VIPER/WRAITH/NOVA-X）——这些属于专有名词。

实现方式：赛道/锦标赛/升级/车型在数据里加了 `zh` 字段，界面通过 `trackName()/champName()/upgName()/bodyName()` 取值；静态文案走 `data-i18n`。切到 EN 时全部回到英文。

## 发车界面 + 名次条

**发车界面**：倒计时期间覆盖整屏，标题「发车顺序」，4 行显示发车名次、头像（程序化头盔）、车手名、车号，玩家行有青色描边和「你」标签，底部「准备起步…」。

**名次条**：比赛开始后左侧常驻 4 行小卡，实时按赛道进度排序 —— 名次、头像、名字、进度条；玩家行高亮，进度条换色。排序变化时重建 DOM，只有进度变化时只改宽度（0.2s 节流）。
